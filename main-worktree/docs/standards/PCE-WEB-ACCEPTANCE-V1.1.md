# PCE-WEB-ACCEPTANCE-V1.1 页面开发与自动验收规范

> 业务动作权限验收规则：前端展示不是权限，服务端验证才是权限。页面按钮的
> 可见、隐藏或禁用不能替代服务端 `Action Permission Validator`；允许和禁止
> 角色都必须通过真实服务端请求验收。

版本：PCE-WEB-ACCEPTANCE-V1.1  
工程治理版本：V1.14.2.8.4.7.50.2

## 1. 目标与适用范围

本规范适用于 Dev-PCE/PCE-ERP 的所有系统公共页面和业务页面。页面开发必须遵循“先注册契约，再继承公共框架，再配置业务差异，最后开发和验收”的顺序。任何页面不得只继承标题或工具栏而绕过完整页面行为契约。

## 2. 页面四级架构

1. **系统公共框架**：路由、登录态、全局导航、页面标题、错误边界、响应式基础和全局诊断入口。
2. **模块固定框架**：模块标准名称、模块布局版本、业务流程、上下游关系、模块导航和权限边界。
3. **页面类型框架**：`list/detail/create/edit/approval/plan/preview/diagnostic` 八类页面的固定区域顺序和行为。
4. **数据和操作层**：服务端读模型、查询、筛选、排序、选择、动作、审计、幂等、导入导出及数据保护。

公共组件不得硬编码具体模块、上下游、业务版本或按钮；业务语义必须来自页面注册表和机器契约。

## 3. 页面公共区域顺序

所有业务页面依次包含：页面框架标题区、当前业务动作说明、模块主流程、业务流程导航、页面动作栏、页面类型专属区域、后续边界、下游零对象保护或诊断。

页面动作栏固定提供：

- 刷新；
- 复制诊断数据；
- 返回业务流程中心。

三项动作必须只读，业务写请求数必须为零。

安全准备阶段允许存在受控准备写入，但必须使用
`PCE-WRITE-INTENT-CONTRACT-V1.0` 分类，不得再把所有非 GET 请求等同为业务
推进。`preview_preparation_write` 只允许保存只读预览或校验快照，
`send_task_preparation_write` 只允许创建经过服务端重验且尚未发送的银行发送
任务，`audit_write` 只允许保存审计证据；`bank_send_execution_write` 和
`business_progress_write` 表示外部发送、财务执行或会计影响，在未显式开放的
准备阶段必须为零。刷新、导航
和复制诊断仍必须零写入。

## 4. 页面类型契约

### 4.1 列表页

页面框架标题区 → 当前业务动作说明 → 模块主流程 → 业务流程导航 → 页面动作栏 → 业务摘要或容量 → 标准工具栏 → 正式列表 → 后续边界 → 下游零对象保护。

### 4.2 详情页

页面框架标题区 → 来源 → 当前状态 → 业务字段 → 规则和校验 → 版本、幂等与审计 → 后续边界 → 诊断。

### 4.3 新建与编辑页

页面框架标题区 → 来源与上下文 → 可编辑业务字段 → 预检查 → 保存边界 → 幂等与审计说明 → 诊断。保存前不得隐式创建下游对象。

### 4.4 审批页

申请信息 → 审批路线 → 当前任务 → 审批历史 → 职责分离 → 按钮权限 → 下游资格。

审批页必须复用服务端共享工作流引擎。页面不得保存审批数组或以客户端状态替代 `WorkflowInstance`、`ApprovalTask` 和 `ApprovalDecision`。审批状态、冻结状态及下游资格必须来自服务端单一事实模型。

进入执行边界的审批页固定显示：当前业务对象 → 审批状态 → 审批历史 → 执行冻结状态 → 服务端执行资格 → 版本、幂等与审计 → 标准列表 → 下游零对象保护。状态动作按服务端状态矩阵显示，未放行的执行动作不得渲染。

### 4.5 计划页

计划日期 → 要求交期 → 进度 → 剩余时间 → 逾期天数 → 紧急程度 → 颜色和文字警示 → 风险排序 → 图例。

### 4.6 预览页

只读标识 → 来源证据 → 预览内容 → 未生成正式对象声明 → 零写入保护。

### 4.7 诊断页

事实来源 → 查询上下文 → 当前状态 → 校验与阻断 → 幂等/编号/事务/审计 → 数据保护说明。

## 5. 标准列表与工具栏

标准列表必须通过公共契约同时实现：

- 快速搜索、完整高级筛选、筛选摘要、逐项清除和全部清空；
- 排序、清除排序、结果/选择/生效筛选计数；
- 多选、清空选择、批量动作及禁用原因；
- 导出当前结果和明确的导入能力声明；
- 加载、空、错误状态；
- 中文枚举、敏感字段脱敏；
- 左侧冻结列、右侧操作列和表格底部横向滚动；
- 1366×768、1920×1080、100%缩放适配，建议补测125%。

同页多表必须分别拥有独立的查询、筛选、排序、选择、滚动和导出状态。

## 6. 快速搜索与高级筛选

快速搜索字段由页面契约声明。高级筛选不得只有一至两个占位字段，必须按业务适用性覆盖对象编号、来源编号、状态、校验、审批、下游资格、组织、业务伙伴、币种、金额、日期、来源模块和阻断类型。

不适用字段必须记录 `applicable=false` 和中文 `reason`，不得静默省略。金额按 Decimal 语义传递，正式业务结论不得使用浏览器浮点运算。

## 7. 多选、批量动作与权限

支持多选时必须冻结选择列和序号列。批量动作必须具有稳定 actionId、权限判定、状态保护、选择数量保护和中文禁用原因。页面按钮必须同时满足页面白名单和权限契约；黑名单动作不得渲染。

## 8. 冻结列与横向滚动

宽表格必须冻结左侧选择列、左侧序号列和右侧操作列。每张表只能有一个横向滚动所有者，滚动条位于表格区域底部，页面主体不得产生额外横向滚动。

真实浏览器验收必须测量 `scrollWidth/clientWidth/scrollLeft/boundingBox`，证明：

- `scrollWidth > clientWidth`；
- 可滚动到最大 `scrollLeft`；
- 左侧列和右侧操作列坐标基本不变；
- 中间列真实位移；
- 固定列背景不透明、z-index正确且有分隔；
- 操作按钮始终可见且可点击。

不得通过缩小字体、删除列、隐藏操作列、增大测试窗口或整页滚动规避。

## 9. 导入与导出

导出基于当前筛选、排序、权限范围和可见业务字段。不得导出完整银行账号、密码、Token、Cookie、JWT、私钥、密钥、完整证件号码或隐藏敏感字段。

导入必须执行：上传 → 格式检查 → 数据预览 → 业务预检查 → 错误报告 → 用户明确确认 → 正式保存。禁止上传后直接写库。不支持导入时必须声明 `importSupported=false` 和中文原因。

## 10. 中文显示与枚举

普通用户页面优先显示中文。技术英文只允许出现在业务编号、系统代码、币种/国际标准代码、脱敏账号、真实英文名称和诊断原始枚举中。

默认映射包括：`prepared=已准备`、`approved=已批准`、`blocked=已阻断`、`validated=已验证`、`draft=草稿`、`committed=已提交`。用户表头必须显示中文业务名称，诊断区可同时显示中文口径和原始枚举。

审批与执行边界默认映射包括：`submitted=已提交审批`、`pending=审批中`、`approved=已审批`、`frozen_for_execution=已冻结待执行`。业务页面不得直接显示这些原始英文枚举。

## 11. 计划类页面

计划状态使用服务端业务日期或服务端派生结果。默认规则：

- 已逾期：红色 + “已逾期”；
- 剩余0—3天：橙色 + “紧急”；
- 剩余4—7天：黄色 + “预警”；
- 剩余超过7天：正常色 + “正常”；
- 完成率100%：绿色 + “已完成”；
- 已取消：灰色 + “已取消”。

颜色不能作为唯一含义，必须显示文字和图例。

## 12. 复制诊断数据

诊断内容来自当前服务端事实，至少包含版本、完整URL、模块、页面、上下游、查询、筛选、排序、结果/选择数量、对象编号、业务/校验/审批/资格、阻断、幂等、编号、事务、审计及下游数量。

审批与执行边界诊断必须包含 `approvalStatus`、`workflowInstance`、`approvalHistory`、`freezeStatus`、`freezeHash`、服务端 eligibility 和 `downstreamCounts`，并与 API、页面和 `strictFacts` 使用同一事实对象。

状态机页面还必须包含 `statusTransitionHistory` 和 `stateMachineConsistent`。所有状态变化必须由服务端状态转换服务写入 `BusinessStateTransition`；状态字段缺少转换记录、审批决策、审计或冻结快照时属于 Level 4 blocker。

诊断不得包含 JWT、Cookie、Authorization、密码、数据库密码、私钥、证书私钥、接口密钥、完整银行账号或未脱敏证件号。复制前后必须证明数据库哈希、业务状态和下游数量不变。存在准备性持久化的页面必须分别记录
`previewPreparationWriteCount`、`auditWriteCount` 和
`forbiddenBusinessProgressWriteCount`，禁止仅以
`businessWriteRequestCount` 作为放行结论。

## 13. 服务端事实与数据保护

正常页面当前状态必须来自服务端读模型。路由参数、页面内存、localStorage、测试注入对象或历史快照不得决定正式业务状态、权限或下游资格。

导航、刷新、诊断默认零业务写入；治理验收不得修改持久演示主库和开发库。破坏性故障注入只能使用测试数据库或持久演示库克隆。

安全准备阶段允许：

- 生成只读预览对象；
- 创建状态最高为 `ready_to_send` 的银行发送任务；
- 保存校验快照；
- 保存审计记录。

只读预览不是业务执行；发送任务准备也不是银行发送执行。安全准备阶段禁止外部发送、财务
执行和会计影响；对应的银行报文、付款执行、资金扣减、银行流水、付款凭证、
总账分录及过账数量必须保持为零。银行发送任务必须经服务端重验、统一权限、
幂等、编号、事务、审计和 `BusinessStateTransition` 管理，且不得进入 `sent`。

## 14. 自动验收五级门禁

1. **Level 1 页面存在**：路由、注册表、组件、标题、可打开。
2. **Level 2 页面结构**：区域顺序、单一主标题、版本分类、流程导航、动作栏、工具栏和正式列表。
3. **Level 3 页面行为**：搜索、筛选、计数、清空、排序、多选、导入导出、冻结列、滚动和操作按钮。
4. **Level 4 业务一致性**：服务端事实、权限、状态、上下游、写入意图分类、禁止业务推进写入和生产数据保护。
5. **Level 5 生产级稳定性**：刷新、状态清理、重新登录、前后端重启、跨进程恢复、数据库哈希、检查点、build和外部归档。

较低等级失败时不得跳过并宣布更高等级通过。

## 15. 报告格式

每个失败记录：版本、契约版本、模块、页面、标准名称、完整URL、区域标题、相对位置、字段或控件、选择器、期望、实际、状态、严重度、原因、截图、Ctrl+F词和数据写入数。

总报告记录模块/页面/注册/通过/失败/断言/blocker/warning数量、首个失败位置，以及是否允许build、检查点和归档。

## 16. Blocker 与 Warning

Blocker 包括路由冲突、页面不可达、标题或版本错误、上下游错误、服务端事实错误、占位筛选、冻结/滚动/操作列失效、整页横向溢出、诊断缺失或泄密、按钮越权、只读动作写入、未分类写入、禁止的业务推进写入、下游对象意外创建、生产数据或数据库保护失败。

Warning 包括非关键长文本、轻微间距、大chunk及非阻断依赖警告。存在任意 blocker 时不得输出通过、生成最终通过检查点或归档。

## 17. 检查点与归档

通过检查点必须包含规范版本、机器契约、页面注册和清单、五级门禁、几何、数据保护、响应式、build和数据库哈希。外部归档必须逐文件比较缺失、额外和哈希不一致数量，三项均为0。

标准命令：

```powershell
npm.cmd run gate:pce-web-acceptance:static
npm.cmd run gate:pce-web-acceptance:runtime
npm.cmd run gate:pce-web-acceptance:all
powershell.exe -ExecutionPolicy Bypass -File .\scripts\Test-PceWebAcceptance.ps1
```

## 18. 开发顺序

固定顺序：注册页面契约 → 继承公共框架 → 配置字段和动作 → 开发页面 → 自动门禁 → 业务检查点 → 外部归档。禁止先开发页面再补验收规则。

审批与状态机实现同时遵循 [PCE-APPROVAL-CONTRACT-V1.1](./PCE-APPROVAL-CONTRACT-V1.1.md) 和 [PCE-STATE-MACHINE-CONTRACT-V1.1](./PCE-STATE-MACHINE-CONTRACT-V1.1.md)。

## 19. 服务端状态转换事实

1. 所有业务状态必须通过统一状态转换服务。
2. 严格页面只能展示服务端返回的转换历史、转换数量和一致性结论，不得由 Provider、Store、页面或复制诊断补造状态历史。
3. `API = 页面 = 复制诊断 = strictFacts` 必须同时覆盖 `sourceState`、`targetState`、`objectType`、`objectId`、`operator`、`timestamp`、`reason`、`version` 和 `auditReference`。
4. `statusTransitionCount` 与服务端历史长度不一致，或任一转换缺少权威审计引用时，Level 4 业务一致性门禁必须失败。
5. `statusTransitionCount` 只能由服务端公共事实模型派生；页面、runtime、复制诊断和 `strictFacts` 不得固定值、不得默认 0、不得从 `statusTransitionHistory.length` 或 `localStorage` 重新计算。
6. 所有暴露状态转换历史的 strict 页面必须接入公共 `status_transition_count_matches_history` 守卫；计数和历史长度不一致时立即形成 blocker。

## 20. 状态机五表面验收

1. 所有业务状态必须经过统一状态转换服务。
2. 五表面事实必须一致：API、页面、复制诊断、`strictFacts`、验收报告。
3. 页面不得对状态转换数量使用默认 0，不得从历史数组或本地状态重新计算；公共运行时校验不通过时必须阻止页面继续形成通过证据。
4. 每个状态机页面的验收证据必须记录完整 URL、区域标题、相对位置、字段名称、期望值、实际值、Ctrl+F 搜索词和通过状态。

## 21. 业务操作动作验收

1. 所有业务操作必须由 Action Registry 驱动。页面不得硬编码生命周期动作、跨模块导航动作、批量业务动作名称、状态矩阵、下一模块路由或权限逻辑。
2. 页面验收必须记录 `currentModule`、`currentStatus`、`availableActions`、`batchActions`、`nextModule`、`nextRoute` 和 `forbiddenActions`，并证明它们来自 `PCE-BUSINESS-ACTION-CONTRACT-V1.0`。
3. 批量动作必须按选择数量、全部所选记录状态、服务端下一步资格和用户权限动态变化。状态改变后仍显示旧动作属于 blocker。
4. 真实行为验收必须覆盖“选择数据 → 执行动作 → 进入下一模块 → 返回 → 继续操作”，并验证动作链没有断裂或隐式创建下游对象。
5. 错误提示关闭后，表格数据、选择状态、冻结列、横向滚动和排序状态必须保持；任一上下文丢失属于 blocker。
6. 银行发送、付款执行、凭证、核销、总账和过账动作未被当前版本显式注册时，必须进入 `forbiddenActions` 且页面不可见。
7. 业务动作页面必须同时证明“数据存在、动作存在、动作可执行、结果可验证”。空表上的按钮静态存在、纯路由模拟或仅检查注册表，不构成真实行为验收通过。
8. 单条动作必须选择且仅选择一条记录；批量动作必须选择至少两条记录。未达到数量边界时，动作必须禁用并返回明确原因。
9. 跨模块动作在导航前必须逐条调用服务端 eligibility API 重新校验；不得信任页面旧内存、URL 参数、客户端 Store、`localStorage` 或动作注册表快照。
10. 真实数据验收必须记录动作前后正式对象数量、服务端资格校验结果、目标路由和下游新增数量，并证明只读导航没有创建下游业务对象。

## 22. V56 四表面事实与错误恢复

1. API、页面、复制诊断和 `strictFacts` 必须复用同一服务端事实对象，并统一声明 `currentStateSource=server`。
2. 四表面的对象数量、状态、转换历史、转换数量和一致性结论必须逐项相等。
3. 页面不得从路由参数、Store、`localStorage` 或测试注入对象补齐正式业务事实。

4. 动作失败或错误提示关闭后，数据、选择、排序、冻结列与横向滚动位置必须保持；不得通过刷新恢复。
5. 遗留页面的可观测性缺口必须进入 `factConsistencyGapReport.json`，未补齐前不得标记为 `migrated`。

## 23. PCE-FACT-LOAD-CONTRACT-V1.0

1. 所有正式服务端读模型必须返回 `factLoadStatus`、`apiUrl`、`httpStatus`、`errorCode`、`errorMessage`、`loadedAt`、`tenantId` 和 `batchId`，API、页面、复制诊断与 `strictFacts` 必须原样一致。
2. `factLoadStatus` 只允许 `loaded`、`empty_valid`、`read_failed`。只有 HTTP 成功且服务端确认结果为空时才能使用 `empty_valid`。
3. HTTP、网络、解析、路由或契约失败必须使用 `read_failed`。此时 `passed=false`，`resultCount` 与容量事实不得伪装为 0，并禁止形成通过报告或检查点。
4. 页面请求层不得将错误响应转换为空数组。API 路径必须经过前端 API Client 与后端 URLConf 契约扫描，404 必须作为失败证据保留。
5. `tenantId` 与 `batchId` 必须由服务端读模型返回；页面只展示，不得硬编码、提交或以本地状态覆盖。
# 可操作金丝雀数据保持

所有用户操作验收页面必须具备服务端可操作金丝雀数据，并继承 `PCE-CANARY-OPERATION-DATA-V1.0`。数据必须覆盖动作前状态、动作后状态和混合选择；API、页面、复制诊断与 `strictFacts` 必须来自同一服务端事实。不得通过页面内存、`localStorage`、路由参数或临时测试注入补造业务状态。
## 24. 事实加载失败完整错误契约

所有 strict 页面必须执行 `PCE-FACT-LOAD-CONTRACT-V1.0`：

1. `read_failed` 必须完整返回非空的 `factLoadStatus`、`apiUrl`、`httpStatus`、`errorCode`、`errorMessage`、`loadedAt`、`tenantId`、`batchId`。
2. 租户和批次来自服务端请求上下文。前端不得硬编码、通过 URL 推断或使用 `localStorage` 补齐。
3. 404、500、timeout、network error 均属于 `read_failed`，不得降级为空数组、默认对象或有效空数据。
4. `read_failed` 时页面、复制诊断和 strictFacts 必须展示同一错误事实；`passed=false`，容量字段不得以 0 冒充成功读取。
5. 页面初始化状态不是服务端事实；禁止用 `FACT_LOAD_NOT_STARTED` 或 `Number(value || 0)` 伪造事实。

## 25. 跨页诊断注册所有权

1. 共享页面壳必须记录当前诊断提供者的页面实例所有权。
2. 旧路由组件卸载时，只能注销自己的诊断提供者；不得清空新路由已经注册的提供者。
3. IAB 验收必须确认复制诊断中的版本、模块、事实对象与当前可见页面一致。
