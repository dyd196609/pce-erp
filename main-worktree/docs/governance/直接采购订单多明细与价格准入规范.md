# 直接采购订单多明细与价格准入规范

版本：`V1.14.2.8.4.27.2.46-Batch2.2-R2`

1. 一个 DIRECT PurchaseOrder 绑定一个 SupplierMaster，并包含 `1..N` 个 PurchaseOrderItem。
2. 先选择 SupplierMaster，再直接加载该供应商 CURRENT SupplierMaterialPrice；每行只选择一个正式价格对象，物料、规格、单位、执行价格、税率和币种均由该对象确定，禁止建立 MaterialMaster 自由选择与价格选择双数据源。
3. 历史、停用、未生效、已失效、跨供应商或跨物料价格均由服务端阻断；阻断原因必须包含“第N行”。
4. 每行持久化 Material、Supplier（订单头）、SupplierMaterialPrice、PriceApprovalResult、数量、含税单价快照、税率快照、币种快照、金额及计划到货日期。
5. 行金额使用 Decimal `quantity × approved_price` 并按分量化；订单总额是所有行金额的 Decimal 合计。
6. Gate 一次校验订单头与全部明细；任意一行失败即整单阻断。预检不写业务数据。
7. 用户顺序固定为：构建明细 → 核对预览 → 点击 Gate → Gate PASS → 人工确认 → 点击创建。
8. 创建 API 再校验 DIRECT 正式授权和签名上下文，采用幂等键；一次事务从同一组已确认行创建一个简化正式 PurchaseRequest、N 个 PurchaseRequestItem、一个 PurchaseOrder 及其 N 个 PurchaseOrderItem，页面不得要求重复录入。
9. 新订单使用 `purchaseMode=DIRECT` 与 `sourceType=DIRECT_PURCHASE_ORDER_CREATION`。不得生成新的 `MANUAL_STANDARD_PURCHASE_ORDER_CREATION`。
10. PurchaseOrder 必须关联 `source_purchase_request`；每个 PurchaseOrderItem 必须关联对应 `source_purchase_request_item`，两端保存相同 SupplierMaterialPrice 编号、单价/税率/币种快照与计划日期。
11. Gate 必须在创建后仍可从服务端 `source_trace.gateCode` 追溯；正式详情必须展示来源申请、精确价格记录、核价结果和“采购申请需求日期”交期来源。
# Batch2.2-R3 人工确认闭环补充

DIRECT 创建按钮必须使用确定状态机表达订单未完成、未 Gate、Gate 失败、待人工确认、可创建、创建中、创建成功和创建失败。Gate PASS 不得自动勾选确认；任何供应商、物料、价格、数量、采购日期或计划到货日期变化必须清除 Gate token 和人工确认。创建成功必须自动跳转统一 PurchaseOrder Detail；创建失败必须显示服务端错误并允许用户重试。
