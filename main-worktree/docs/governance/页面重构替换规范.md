# 页面重构替换规范

- 规则编号：`PAGE-MIGRATION-001`
- 生效版本：`V1.14.2.8.4.27.2.6`
- 适用范围：包含重构、替换、升级页面或重新设计的任务
- 状态：长期有效

## 1. 强制替换链

页面重构前必须找到旧页面入口、旧Route Component、旧渲染链和旧运行证据；实施后必须将真实Router入口切换到新页面，并扫描全部入口与动态加载关系。

标准证据：

```text
Old Page: <旧页面>
Old Route Component: <旧路由组件>
Old Render Chain: <旧渲染链>
New Page: <新页面>
New Route Component: <新路由组件>
Old Renderer Used: YES/NO
```

## 2. 禁止孤立新页面

新增文件但Router仍指向旧组件、只在测试中import新组件、只增加不可达预览入口，均判定迁移失败。新页面必须由任务指定的真实URL直接访问。

## 3. 旧渲染器清理

必须删除旧Route分支对旧详情渲染器的挂载和import。允许保留仍被其他职责合法使用的公共组件，但必须证明它不再承担已替换的Route Renderer。`Old Renderer Used=YES`时`PAGE-MIGRATION-001`为FAIL。

## 4. 回归与恢复

切换前冻结旧入口、对象身份和禁改资产哈希；切换后验证列表进入、直接URL、刷新、关闭重开、历史对象和返回列表。新入口失败时应能依据版本差异恢复Router映射，不得修改业务数据回避问题。

## 5. PAGE-MIGRATION-002 Active Runtime替换检查

页面壳或Route Component已经替换，但其内部仍挂载旧详情Renderer、GenericDetailRenderer、旧CRUD详情组件、旧编号布局或旧物料表布局时，迁移仍为FAIL。验收必须从真实Route逐层记录`Route Component -> Active Runtime Component`，并输出：

```text
Old PurchaseOrder Detail Renderer: NOT USED
Old Layout: REMOVED
New Layout: ACTIVE
```

旧组件可以作为历史资产保留，但不得被新Route Component直接或间接import、动态加载或条件挂载。
