# 供应商主数据规范

> V1.14.2.8.4.27.2.45.11 补充：开发测试阶段允许按 `MASTER-DATA-REVERSE-ENRICHMENT-001` 从唯一、可审计采购业务事实反向补全缺失 SupplierMaster。业务事实字段与开发补全字段必须分开记录，供应商地址与送货地址继续独立维护。

- 规则编号：`SUPPLIER-MASTER-SOURCE-001`
- 生效版本：`V1.14.2.8.4.27.2.24`
- 适用范围：SCM供应商、物料供应关系、价格事实及采购订单
- 状态：长期有效、持续更新
- 关联规范：`价格事实治理规范.md`

## 1. 唯一来源链

```text
SupplierMaster
-> MaterialSupplierRelation
-> SupplierMaterialPrice / SupplierQuoteItem
-> PurchaseOrderItem
```

`SupplierMaster` 是供应商身份、名称、联系资料、注册地址和物流送货地址的唯一权威来源。采购订单必须保存真实 `Supplier` 关系，不得仅保存Gate、报价或页面文本。`address`表示注册地址，`deliveryAddress`表示物流送货地址，两者必须独立持久化。

## 2. 供应商物料关系

`MaterialSupplierRelation` 必须同时指向有效 SupplierMaster 和 MaterialMaster。本期在不修改数据库结构的边界下，只有服务端持久化 `SupplierQuotation.items` 中能同时验证供应商和物料的行，才能投影为可用关系事实。前端Store、页面选择和Gate快照不是权威关系。

## 3. 价格与联系资料边界

- 价格优先读取已接收的 `SupplierQuoteItem.unitPrice`；其次才允许取受治理的 `SupplierMaterialPrice`。
- 无正价事实时必须阻断订单创建，禁止默认 0、MaterialMaster价格或页面手填价格。
- 联系人、电话、注册地址和物流送货地址只能读取 SupplierMaster。脱敏只是展示处理，不得反写或伪造主数据。

## 4. 验收门禁

- `SUPPLIER-SOURCE-TRACE-001`：订单可追溯到SupplierMaster及上游推荐/报价。
- `SUPPLIER-MATERIAL-RELATION-001`：供应商和物料的联合身份已被服务端事实验证。
- `PURCHASE-PRICE-SOURCE-001`：单价大于0且来源可追溯，金额由服务端计算。
- `SUPPLIER-CODE-MATCH-001`：SupplierMaster与价格/关系事实必须通过服务端主键或完整供应商编码严格匹配；仅允许去除首尾空白和统一大小写，禁止删改连字符、前缀或数字位数。

## 5. 统一事实解析

采购订单创建必须调用 `SupplierMaterialFactResolver`。解析器输入 SupplierMaster、MaterialMaster、SupplierMaterialPrice 和 MaterialSupplierRelation，输出统一的供应商、物料、价格与交期事实。数据库结构冻结期间，SupplierMaterialPrice 与 MaterialSupplierRelation 可由持久化 SupplierQuotation 行投影，但页面私有 Store、Gate价格和名称模糊匹配均不得进入解析器。

价格事实的物料、供应商、时间、有效期、来源和人工边界继续执行`PRICE-FACT-MODEL-001`与`PRICE-SOURCE-TRACE-001`。本规范中的SupplierMaterialPrice是既有Runtime投影，不授权新建第二价格模块或持久化体系。
