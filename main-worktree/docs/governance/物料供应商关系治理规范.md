# 物料供应商关系治理规范

- 规则编号：`MATERIAL-SUPPLIER-SOURCE-001`
- 生效版本：`V1.14.2.8.4.27.2.30`
- 适用范围：MaterialMaster 与 SupplierMaster 的正式供应关系、业务引用和页面展示
- 状态：长期有效、持续更新

## 1. 唯一事实

`MaterialSupplierRelation` 是唯一物料供应关系来源。正式链路固定为：

```text
Persisted Business Facts
-> MaterialSupplierUsageMatrix
-> MaterialSupplierRelation Runtime
-> Provider / API
-> Foundation Page / Business Reference
```

业务模块只能引用关系，不得自行建立第二份关系。采购订单不得根据名称、Gate 或页面上下文自行判断供应商；价格模块不得以价格记录反向创建未经业务事实证明的供应关系；验收、Demo 与页面私有 Store 数据不得进入正式业务链。

## 2. 来源优先级

同一 MaterialMaster + SupplierMaster 组合的来源优先级为：

1. 已持久化供应商推荐结果；
2. 已持久化核价结果；
3. 已持久化供应商报价事实；
4. 已持久化采购历史事实。

没有能够严格映射双方主数据编码的业务事实时，不得自动创建关系；仅在 `MaterialSupplierUsageMatrix` 中记录“待人工确认”。

## 3. 身份与唯一性

- `MATERIAL-SUPPLIER-UNIQUE-001`：`materialCode + supplierCode` 在 Runtime 中唯一。
- `MATERIAL-SUPPLIER-MAPPING-001`：关系双方必须分别严格匹配 `MaterialMaster.materialCode` 与 `SupplierMaster.supplierCode`。
- 只允许去除首尾空白；禁止改变大小写、删除前缀、删除符号、补零、名称匹配或猜测映射。
- `MT001`、`mt001`、`MAT-001` 是不同业务编码；不能自动合并。

## 4. 关系字段

`MaterialSupplierRelation Runtime` 必须输出：

- `relationCode`
- `materialCode`、`materialName`
- `supplierCode`、`supplierName`
- `isMainSupplier`
- `priority`
- `deliveryPeriod`
- `qualityLevel`
- `onTimeRate`
- `status`
- `sourceReference`
- `sourceModules`、`businessUsageCount`

`relationCode` 由双方正式编码确定，只标识关系事实，不改写双方编码。

## 5. 主供应商与交期

- 主供应商只允许由明确的供应商推荐结果、核价结果或报价比较结果证明；没有明确事实时必须为 `false`。
- `deliveryPeriod` 优先读取 SupplierQuotation，其次读取已受治理的 SupplierMaterialPrice；人工测试基础数据必须具有独立授权并记录 `sourceReference`。
- 无来源时 `deliveryPeriod` 保持空值，不得填写默认天数。
- 质量等级、准时率无权威事实时保持“待评估”与空值，不得前端推算。

## 6. 页面与统计

`#/foundation/erp/material-suppliers` 必须读取 `MaterialSupplierRelation Runtime`，禁止读取 `manufacturingFoundationStore.materialSupplierRelations`。

首页关系数量必须满足 `MASTER-DATA-STATISTICS-RELATION-001`：

```text
MasterDataStatisticsRuntime.supplierMaterialRelationCount
= MaterialSupplierRelationRuntime relation count
= Foundation Page displayed count
```

## 7. 写入边界

本规范允许受控补全关系基础资料，但不授权修改 MaterialMaster、SupplierMaster、SupplierMaterialPrice、PurchaseRequest、PurchaseOrder 或 Gate。若当前数据库结构冻结，则允许以只读 Runtime 对既有持久化业务事实建立正式关系投影；该方式 `Business Transaction Write Count = 0` 且 `Database Structure Changed = NO`。
