## 2. 执行前编码一致性扫描

### 页面私有基础资料集合

```text
SupplierMaster: SUP001
SupplierPrice:  SUP-000001（内部 supplierId=sup-001）
是否一致: FAIL

MaterialMaster: MT001
SupplierPrice:  MAT-000001（内部 materialId=mat-001）
是否一致: FAIL
```

两组编码不仅格式不同，物料名称和业务语义也不相同。禁止通过删除连字符、替换前缀或序号映射强行合并；该前端 Store 不再作为采购订单事实来源。

### 服务端权威事实集合

```text
SupplierMaster: SUP001 / id=1
SupplierQuotation: supplierId=1
Resolver Output: SUP001
是否一致: PASS

MaterialMaster: MT004 / id=6
SupplierQuoteItem: materialId=6, materialCode=MT004
Resolver Output: MT004
是否一致: PASS
```

## 3. 统一运行链

```text
SupplierMaster + MaterialMaster
              +
SupplierQuotation.SupplierQuoteItem
              ↓
SupplierMaterialFactResolver
              ↓
PurchaseOrderItem
```

解析器同时验证供应商、物料的服务端主键/完整编码。输入中的主键与编码只要有一项冲突即拒绝，禁止名称匹配和编码重写。

## 4. 订单事实

- Supplier：来自 SupplierMaster。
- Unit Price：来自持久化 SupplierQuoteItem；必须大于0。
- Amount：服务端计算 `quantity × unitPrice`。
- Delivery：报价交期、受治理交期周期、采购申请需求日期依次回退。
- 缺失或编码冲突：整笔事务阻断，写入数0。
