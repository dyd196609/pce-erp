# 供应商采购链智能化升级评估报告

- 版本：`V1.14.2.8.4.27.2.33`
- 英文输出：`SupplierChainIntelligenceCapabilityInventory`、`PriceFactModelAssessment`、`PriceFactDataQualityReport`
- 任务类型：治理与规划，不开发价格模块，不修改业务数据或数据库
- 评估链：`SupplierMaster -> MaterialSupplierRelation -> SupplierMaterialPrice -> SupplierQuotation -> QuoteComparison -> PriceApproval -> SupplierRecommendation -> PurchaseOrder`

## 1. 智能化影响评估

供应商采购链已具备严格主数据匹配、报价Runtime投影、不可变比价事实、人工核价Guard、推荐证据和订单创建前服务端复核。直接新增价格模块会复制现有Runtime并割裂事实链。安全路线是扩展现有`SupplierMaterialPriceRuntime`为统一Price Fact Runtime契约；数据库持久化、历史迁移和业务写入均暂缓到独立授权版本。

## 3. PriceFactModelAssessment

### 3.1 当前模型

| 对象 | 当前事实 | 缺口 |
|---|---|---|
| `SupplierMaterialPrice` | 无独立持久化表；由`SupplierQuotation.items.unitPrice`经`SupplierMaterialPriceRuntime`投影 | 缺事实类型、有效期、版本、税口径和历史聚合 |
| `SupplierQuotation` | 持久化供应商、币种、状态、接收时间、头价格和JSON明细价格 | 明细有效期不是强制字段；仅1条现存报价 |
| `QuoteComparisonFact` | 模型支持不可变多供应商证据、最低价、版本和人工核验 | 当前数据库0条，无法提供正式比较历史 |
| `PriceApprovalPreparation` | 支持来源比较、候选、人工结论和`historical_price_reference` | 13条历史引用全部为空；存在Legacy投影链 |
| `PriceApproval` | 支持供应商、价格和审批状态，PurchaseOrder有来源外键 | 当前0条；210张订单均未绑定该来源字段 |
| `PurchaseOrderItem` | 持久化执行单价，服务端创建链可记录`priceSource` | 历史订单来源结构不完整，13条明细为非正价 |

### 3.2 价格维度结论

| 分析项 | 结论 |
|---|---|
| 价格来源 | 报价明细来源存在；比价/核价/订单历史链覆盖不足 |
| 价格生命周期 | 业务节点存在，但尚未形成统一四类Price Fact契约 |
| 供应商关联 | 报价可按ID或完整编码严格匹配SupplierMaster |
| 物料关联 | 报价明细可按ID或完整编码严格匹配MaterialMaster |
| 有效期 | 模型/现存报价未形成强制完整契约；当前报价明细缺失 |
| 历史价格 | 有容器但现有13条核价准备全部为空 |
| 最低价 | 单个有效样本可计算，但当前无正式QuoteComparisonFact，不可用于选择 |
| 最近价 | 唯一样本有时间可识别；没有足够历史验证稳定排序 |
| 变化趋势 | 同物料供应商组合不足两个时间点，当前不可计算 |

## 4. Price Fact Runtime规划

```text
SupplierQuotation/SupplierQuoteItem（报价事实）
  -> QuoteComparisonFact（价格比较事实）
  -> PriceApprovalPreparation/PriceApproval（人工核价事实）
  -> PurchaseOrderSupplierFactRuntime（创建前复核）
  -> PurchaseOrderItem.unit_price（执行价格事实）
```

规划中的Price Fact Runtime是`SupplierMaterialPriceRuntime`的扩展契约，不是新模块。它以物料、供应商、时间、币种、税口径、有效期和来源身份生成不可变只读投影；页面只显示Runtime结果，Gate只传身份，PurchaseOrder页面不得匹配或计算价格。

## 5. 智能化升级判断

| 项目 | 结果 | 依据与边界 |
|---|---|---|
| 自动价格匹配 | 需扩展 | 严格Material+Supplier匹配已可复用；缺有效期、税口径和历史覆盖，只能给候选，人工确认 |
| 价格上涨检测 | 需扩展 | 需要至少两个同口径有序价格点；当前为0个可计算趋势组合 |
| 异常低价/高价 | 需扩展 | 通用规则引擎可复用，但缺业务阈值、样本窗口与规则版本 |
| 供应商偏离 | 需扩展 | 需同物料候选集合和稳定历史，当前正式比较事实为0 |
| 供应商智能推荐 | 需扩展 | 已有推荐证据能力，但价格、交期、质量和绩效需统一事实完整性与权重版本 |
| 自动选择或审批 | 不可用 | 违反人工决策边界；不得自动选最低价、核价、推荐确认或创建订单 |

## 6. 人工决策边界

必须人工确认：报价接收与更正、可比口径、核价结论、异常豁免、供应商选择、推荐确认、采购数量、执行价格、交期、PurchaseOrder创建与审批。系统只可生成匹配候选、数据缺口、异常提示、统计参考和来源解释；所有建议必须显示样本量、数据完整性、规则版本及`PASS/FAIL/UNKNOWN`。

## 8. 数据治理建议

1. 先为未来报价事实强制有效期、币种、税口径、事实时间和来源行身份，不修改历史记录。
2. 对Legacy订单建立只读缺口清单；没有原始报价/核价证据时保持`UNKNOWN`，禁止补造来源。
3. 独立测试数据版本可为关键物料-供应商组合补充多时间点`TEST_BASE_PRICE`，必须标记`DEVELOPMENT_TEST_DATA/isTestBasePrice=true`，与真实报价隔离。
4. 在至少具备两个同口径时间点前，趋势与异常检测保持`INSUFFICIENT_DATA`。
5. 任何数据补充都必须另立授权版本；本版本不写入。
