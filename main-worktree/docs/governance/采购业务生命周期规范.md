# 采购业务生命周期规范

- 规则编号：`SCM-PURCHASE-LIFECYCLE-001`
- 生效版本：`V1.14.2.8.4.27.2.24`
- 适用范围：采购申请至采购订单及后续执行
- 状态：长期有效、持续更新
- 关联规范：`价格事实治理规范.md`

## 1. 权威业务链

```text
PurchaseRequestItem
-> PurchaseInquiry
-> SupplierQuotation / QuoteComparison
-> SupplierRecommendation
-> PurchaseOrderGate
-> PurchaseOrderCreationRequest
-> PurchaseOrder + PurchaseOrderItem
```

Gate只表达准入结果与上游身份，不得成为供应商主数据、价格、交期或物料基础字段的第二事实源。

## 2. 采购订单创建门禁

创建前必须在服务端重新验证：

1. 供应商绑定到启用的 SupplierMaster；
2. 物料绑定到 MaterialMaster 和唯一 PurchaseRequestItem；
3. 单价来自 SupplierQuoteItem 或受治理 SupplierMaterialPrice，且大于0；
4. 交期依次取 SupplierQuote.deliveryDate、SupplierMaterialPrice.deliveryPeriod、PurchaseRequest.requiredDate，不得为空；
5. `amount = quantity × unitPrice`，`PurchaseOrder.totalAmount = SUM(item.amount)`，两者必须大于0。

任一事实缺失时整笔事务阻断，Business Write Count 必须为0。

## 3. 来源追踪

PurchaseOrderItem 必须输出 `supplierSource`、`priceSource`、`deliverySource`、上游报价编号、PurchaseRequestItem和MaterialMaster身份。页面只消费服务端投影，不得重新计算价格、金额或交期。

## 4. 验收门禁

- `PURCHASE-AMOUNT-CALC-001`：行金额和订单总额算术一致。
- `PURCHASE-DELIVERY-SOURCE-001`：每行交期非空且来源合法。
- `PURCHASE-ORDER-SUPPLIER-FACT-001`：供应商、价格、金额和交期门禁同时通过才允许创建。
- `PURCHASE-ORDER-FACT-INHERIT-001`：PurchaseOrderItem必须通过 `SupplierMaterialFactResolver` 继承严格匹配的 supplier、material、unitPrice、amount 和 deliveryDate；不得读取Gate价格或由页面计算。

采购订单执行价格还必须遵守`PRICE-SOURCE-TRACE-001`：服务端按报价事实、比较事实、人工核价事实和执行价格事实逐层复核；Gate和页面不得成为价格来源。历史来源缺失时保持Legacy/UNKNOWN，不得反向伪造报价或核价事实。
