# 供应商主数据完整性规范

- 规则编号：`SUPPLIER-FIELD-COMPLETE-002`、`SUPPLIER-DUPLICATE-REVIEW-001`
- 生效版本：`V1.14.2.8.4.27.2.27`
- 适用范围：`procurement.Supplier`（SupplierMaster）及供应商主数据维护页面
- 状态：长期有效、持续更新

## 1. SupplierMaster 完整性

SupplierMaster 必须持久化并完整提供以下基础字段：

- 编码；
- 名称；
- 分类；
- 地址；
- 联系人；
- 联系电话；
- 状态；
- 等级。

地址、分类、联系人和联系电话不得为空；`未维护`、`未分类`等展示占位值不计为完整。测试数据可以使用模拟企业地址、通用联系人和非真实个人联系电话，但不得使用真实个人信息。

供应商地址统一采用“省 + 市 + 公司”结构。无法从已知业务类型判断分类时必须持久化为`待分类`，不得保留空值。

## 2. 唯一事实边界

供应商编码、名称、分类、地址、联系人、联系电话、状态和等级的唯一权威来源是 SupplierMaster。业务模块只能引用供应商身份或保留业务时点快照，不得补充、推断或反写供应商基础字段。

供应商页面、API、复制诊断、`strictFacts`与验收报告必须读取同一 SupplierMaster 服务端事实；禁止使用页面缓存、静态测试行或前端重算补齐字段。

## 3. 同名供应商审核

同名供应商禁止自动合并、删除或修改编码。每条存在同名歧义的 SupplierMaster 必须进入独立的 `SupplierDuplicateReview` 审核记录，至少包含：

- 供应商编码；
- 供应商名称；
- 重复原因；
- 处理状态。

初始处理状态固定为`待人工确认`。审核记录只表达主数据治理待办，不得推进采购、Gate、报价、付款或银行发送业务状态。

## 4. 验收门禁

- `SUPPLIER-FIELD-COMPLETE-002`：全部 SupplierMaster 的地址、分类、联系人和联系电话均为非空有效值，且不使用未维护占位值。
- `SUPPLIER-DUPLICATE-REVIEW-001`：每个同名 SupplierMaster 均存在状态为`待人工确认`的审核记录；供应商编码、记录数量和身份保持不变。
- 供应商维护页面必须通过 SupplierMaster Runtime 展示上述服务端事实。
- 基础资料维护写入允许；采购订单、Gate、报价、物料及其他业务交易写入必须为零。

任一适用门禁为 `FAIL` 或 `UNKNOWN` 时，不得输出 `SUPPLIER_MASTER_COMPLETENESS_READY`。
