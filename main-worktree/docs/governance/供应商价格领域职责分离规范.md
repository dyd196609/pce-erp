# 供应商价格领域职责分离规范

- 版本：`V1.14.2.8.4.27.2.43`
- 规则编号：`PRICE-DOMAIN-SEPARATION-001`
- 上位规范：`PCE-ERP智能化开发总纲.md`、`价格事实治理规范.md`
- 适用范围：供应商关系、企业认可有效价格、价格事实与采购核价辅助

## 1. 三个对象的唯一职责

| 对象 | 回答的问题 | 允许承载 | 禁止承载 | 正式所有者 |
|---|---|---|---|---|
| `MaterialSupplierRelation` | 哪些供应商可以供应该物料？ | 物料、供应商、主供应商、供应优先级、交期、质量等级、准时率 | 采购历史价格、企业认可价格、报价决定 | `MaterialSupplierRelationRuntime` |
| `SupplierMaterialPrice` | 当前企业认可的供应价格是多少？ | 合同/协议/人工维护价格、币种、税率、最小采购量、交货周期、有效期、来源、审批状态 | 历史采购价格、页面临时价格、未审批执行价 | 既有`SupplierMaterialPriceRuntime`；只读投影完整且受治理的正式有效价格 |
| `SupplierPriceFact` | 过去实际价格和可追溯来源是什么？ | 报价事实、受治理有效价格候选、采购订单历史、时间与来源 | 人工编辑、覆盖历史、自动核价或自动选供应商 | `SupplierPriceFactRuntime` |

三个对象不得相互覆盖或共享同一条可变记录。`SupplierMaterialPrice`进入核价或订单执行前，必须具备服务端持久化身份、来源类型、来源编号、审批状态和有效期；缺少任一项时只能标记`NOT_GOVERNED`，不得由页面、Gate或前端Store补造。

## 2. SupplierMaterialPrice正式契约

V1.14.2.8.4.27.2.42在既有运行层内确认正式契约：`supplierId`、`materialId`、`unitPrice`、`currency`、`taxRate`、`minOrderQty`、`deliveryPeriod`、`effectiveDate`、`expiryDate`、`sourceType`、`sourceReference`、`approvalStatus`。`SupplierMaterialPriceRuntime`只投影字段完整、主数据可绑定且审批状态受治理的记录；任何字段缺失均进入迁移评估并保持隔离。

当前数据库没有满足完整契约的记录，因此正式价格数量为0。该结果表示“未发现可安全认定的企业有效价格”，不是页面缺数，也不得通过页面默认值、采购申请数量或报价总额补造。

V1.14.2.8.4.27.2.43起，既有Runtime的归档规则固定为：

```text
SupplierQuotation
  -> HumanPriceApproval
  -> SupplierMaterialPriceRuntime（完整记录只读投影）
```

允许来源类型仅为`Quotation Approved`与`Manual Approved Price`。报价来源必须具有报价编号和已审批状态；人工维护来源必须具有独立人工确认对象和来源编号。Runtime不得替任何缺失字段设置默认值，`autoGenerationEnabled`必须保持`false`。

页面允许查看，并提供“编辑价格（进入核价流程）”受控入口。维护模式为`APPROVAL_WORKFLOW_MANAGED`：修改必须经核价流程形成新版本，不直接改写运行投影。禁止删除历史事实，禁止把“默认价格”直接解释为已审批执行价格。

## 3. PurchasePriceReview只读输入链

```text
MaterialSupplierRelationRuntime
  + SupplierMaterialPrice（仅正式受治理事实；缺失时NOT_GOVERNED）
  + SupplierPriceFactRuntime（历史执行事实与分析）
  + SupplierQuotationItem（当前报价事实）
  -> PurchasePriceReviewContext
  -> 人工核价确认
```

页面必须逐项显示输入所有者和可用状态。`NOT_GOVERNED`或`UNAVAILABLE`不得被默认值替代。智能核价只汇集证据、比较和提示；禁止自动决定供应商、自动确定价格、自动修改价格或自动生成采购订单。

## 4. 页面边界

- `#/foundation/erp/supplier-material-prices`：企业有效价格定位；正式列表仅来自`SupplierMaterialPriceRuntime`，早期演示源保持隔离。
- `#/foundation/erp/supplier-price-facts`：只读事实；操作策略固定为`view`。
- `#/foundation/erp/material-suppliers`：供应关系主数据；不得出现采购历史价格维护。
- `#/scm/price-review-assistant`：显示四类输入及其状态，只提供人工决策参考。

## 5. 验收门禁

- `PRICE-DOMAIN-SEPARATION-001`：三个对象的问题、字段、来源和禁止边界可独立检索。
- `PRICE-SOURCE-TRACE-001`：所有可用价格具有来源类型、来源编号、供应商、物料和时间；缺失显式阻断。
- `PRICE-INTELLIGENCE-CHAIN-001`：核价输入链完整声明且无自动决定。
- `NO-DUPLICATE-PRICE-MODEL-001`：未新增第二套价格、Runtime、Metadata或页面框架。
- `REAL-BROWSER-EVIDENCE-001`：四个指定页面具有当前版本截图和可见职责证据。
# V1.14.2.8.4.27.2.44 报价确认补充规则

- `PurchasePriceReviewAssistant` 的报价确认属于核价结果人工确认，不是报价审批中心。
- 人工结果仅允许：接受报价、拒绝报价、要求重新议价。
- 只有接受报价可以请求 `SupplierMaterialPriceRuntime` 形成有效价格；拒绝和重新议价不得生成价格。
- 服务端必须重新读取 `SupplierQuotation` 权威事实，页面不得提交或改写供应商、物料、报价单价和币种。
- 本版本有效价格为 `SERVER_MEMORY_ONLY` 会话投影，必须标记 `SupplierQuotationConfirmed`、`SESSION_CONFIRMED`、`persisted=false`，不得伪装为数据库持久化价格。
- 会话有效价格不得进入 `SupplierPriceFact` 历史事实，不得驱动采购订单、Gate 或供应商自动选择。

## V1.14.2.8.4.27.2.45.7 归档与维护边界

- `PriceApprovalPreparation` 的“已完成”是流程状态，不是有效价格存在证明。
- `SupplierMaterialPrice` 只接受可追溯到正式报价明细、人工核价通过且显式确认的来源。
- 页面来源名称由统一映射提供中文 `sourceTypeLabel`，底层 `sourceType` 保持原编码。
- 企业默认采购税率通过既有服务端配置层进入 `SupplierMaterialPriceRuntime`，页面组件不得写死默认税率。
- `SupplierMaterialPrice` 人工维护仅限税率、生效日期、失效日期；供应商、物料、单价、币种、来源身份只读；交货周期仍归 `MaterialSupplierRelation`。
- 税率维护属于主数据价格配置写入，不触发报价、核价、推荐、订单或历史价格事实写入。

## V1.14.2.8.4.27.2.45.8 决策事实边界

- `PriceApprovalResult` 是人工确认后的最终价格批准事实；`SupplierMaterialPrice.priceApprovalResult` 必须一对一追溯。
- `SupplierQuotation`、`legacy_verified_fact`、`development_test_data` 都是原始输入类型，不得互相改名。
- 历史事实不能直接归档，但经新的核价、供应商选择和确认动作后，可由新的 `PriceApprovalResult` 形成有效价格。
- 正式有效价格必须数据库持久化；服务器内存投影不得承担正式价格所有权。
- `effectiveDate` 取真实人工事件，`expiryDate` 默认空且只允许人工维护。

## V1.14.2.8.4.27.2.45.9 运行闭环边界

- `SupplierMaterialPriceRuntime（供应商物料价格运行层）` 只读取数据库正式模型；Session Memory 不能进入正式列表。
- 核价页显示“待确认报价”前必须通过 SupplierMaster 与 MaterialMaster 映射预检；映射失败统一显示“不允许归档”和中文阻断原因。
- 页内刷新必须强制重新请求同一 Runtime API，不得创建第二 Provider 或调用浏览器整体刷新。
