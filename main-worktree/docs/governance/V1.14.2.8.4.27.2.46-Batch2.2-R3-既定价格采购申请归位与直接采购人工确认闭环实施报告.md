# V1.14.2.8.4.27.2.46-Batch2.2-R3 实施报告

## 版本边界

- Previous R2 Human Acceptance：`FAIL`
- R2 禁止标记 READY；本版本不进入 Batch3。
- 本版本只修复 AGREED_PRICE 申请入口和 DIRECT 人工确认创建闭环。

## Batch2.2-R3 Existing Object Chain Scan

1. 采购申请入口为 `ScmPurchaseRequestPage.vue`；STANDARD 正式表单为 `ScmPurchaseRequestOriginalBusinessRegion.vue`。
2. R2 的 AGREED_PRICE 路由指向 `ScmAgreedPricePurchaseFoundationPage.vue`，页面只读取 SupplierMaterialPrice CURRENT 列表，没有创建 PurchaseRequest。
3. PurchaseRequest 正式链为 `PurchaseRequest/PurchaseRequestItem -> PurchaseRequestSerializer -> PurchaseRequestViewSet -> purchaseRequestApi -> ScmPurchaseRequestOriginalBusinessRegion`。
4. PurchaseRequestItem 的物料由 Serializer 按 MaterialMaster 主键解析；STANDARD/AGREED_PRICE 申请阶段不要求 SupplierMaterialPrice。
5. DIRECT 正式链为 `ScmPurchaseOrderCreateEntryPage -> PurchaseOrderGateCreationView -> PurchaseOrderCreationService -> PurchaseOrder/PurchaseOrderItem`；服务端复核 Supplier、Material、MaterialSupplierRelation、SupplierMaterialPrice CURRENT、权限、token 与幂等键。
6. DIRECT 创建已由 `transaction.atomic` 同时持久化来源 PurchaseRequest、N 条 PurchaseRequestItem、PurchaseOrder 与 N 条 PurchaseOrderItem。
7. R2 仓库中没有覆盖“真实点击 checkbox -> 按钮 enabled -> 点击创建”的浏览器脚本。旧专项脚本是静态源码/API 断言，R2 证据也缺少人工确认已勾选截图，因此 R2 PASS 没覆盖人工失败路径。

## 实施结果

- AGREED_PRICE 页面改为“新建既定价格采购申请”，直接复用正式 PurchaseRequest 表单、基础资料 provider、MaterialMaster 选择器和保存 API。
- `purchaseMode=AGREED_PRICE` 由同一 Serializer 持久化；申请明细不绑定价格记录。
- 服务端 inquiry eligibility、询价创建服务和可询价列表均只允许 STANDARD；AGREED_PRICE 审批后事实状态为 `AGREED_PRICE_PURCHASE_REQUEST_READY_FOR_PRICE_CONFIRMATION`。
- DIRECT 形成 `ORDER_INCOMPLETE -> GATE_REQUIRED -> GATE_FAILED/HUMAN_CONFIRMATION_REQUIRED -> READY_TO_CREATE -> CREATING -> CREATED/CREATE_FAILED` 确定状态机。
- checkbox 只能由用户交互改变；Gate 或订单内容变化会清除 token 和人工确认。
- 创建请求继续由服务端重算准入，在同一事务内持久化；创建成功自动跳转统一 PurchaseOrder Detail，失败保留重试能力并展示服务端错误。

## R2 假阳性根因

根因是验收覆盖缺口：R2 报告引用了数据库中已创建订单，但仓库不存在与该报告对应的真实 UI 操作脚本；现有 `verifyPurchaseOrderDirectCreationV11428427246Batch22.mjs` 不点击 checkbox 或创建按钮，只做源码与既有 API 数据断言，且包含已过时页面结构。故它不能证明用户当前页面的按钮闭环。

## 停止状态

自动验收完成后仍只能停在 `AGREED_PRICE_PURCHASE_REQUEST_AND_DIRECT_CREATION_CLOSURE_WAITING_HUMAN_ACCEPTANCE`，Human Acceptance 必须为 `WAITING`。
