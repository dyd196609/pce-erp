# PCE-ERP页面与交互开发规范

# 文档信息

- 版本：V1.14.2.8.4.27.2.4.3
- 用途：统一页面身份、结构、企业列表、动作、可观测性和单页验收
- 适用范围：PCE-ERP全部可访问页面和公共页面组件
- 优先级：高
- 关联规范：05自动验收、06模块专项、07案例库
- 维护方式：持续更新

## 1. 页面固定结构

所有业务页面按以下语义结构组织：

```text
页面标题
  -> 业务说明
  -> 状态区域
  -> 数据区域
  -> 操作区域
  -> 诊断区域
  -> 验收区域
```

区域可以由Page Shell提供，但业务页面不得重复建设公共顶部、标题、流程导航、列表基座或诊断框架。空区域必须显示明确业务空状态，禁止因`v-if`卸载列表契约。

## 2. Page Identity与业务名称

- 每页声明`pageCode/pageName/moduleCode/businessObject/route`，并与Registry、Router、流程中心一致。
- 业务名称唯一来源是BusinessNameRegistry；禁止fallbackTitle、route.meta.title/pageName、局部canonicalName、currentList.title或页面硬编码成为第二名称源。
- Route只表达稳定页面身份；业务数据由Context Resolver恢复。
- 页面壳必须消费Registry和受治理版本事实，不得覆盖业务页面名称。

## 3. 页面开发模板

页面Contract至少包含：身份、用途、角色、输入Provider、运行模式、状态、区域、字段、Action Contract、Guard、上一步、下一步、异常、可观测性和验收Profile。创建、详情、编辑、列表和审批页分别声明职责，禁止用一个页面承载互斥节点。

## 4. 状态与业务语言

用户页面只显示服务端`statusLabel`；`statusCode`仅用于内部治理、筛选和协议，不直接展示给业务用户。业务结论、流程状态、审批状态分别展示。未知值显示明确“未知/待确认”，不得直接回退英文技术码。

## 5. 企业级列表标准

所有企业列表必须接入`PCE-ENTERPRISE-LIST-CONTRACT-V1.1`、`PceEnterpriseListTable`、`PceEnterpriseAdvancedFilter`和`PceBusinessStatus`，并具备：

- 快速筛选和清空；
- 字段驱动高级筛选；
- `remote-select`编号/主数据选择；
- 批量筛选和选择统计；
- 排序、分页、导出和清空选择；
- 左侧固定选择框、序号、主业务编号；
- 右侧固定Action Column；
- 固定列必须分别遵守左侧身份列与右侧操作列所有权；
- 表格内部唯一横向滚动；
- 空数据时仍保留筛选、列头和滚动容器。

### 5.1 筛选

字段必须声明`field/label/filterType或type/optionsSource`。枚举使用受治理`select`，日期使用`date/daterange`，编号使用受治理`remote-select`。页面不得自行创建筛选控件或拼装未声明选项。

### 5.2 Action Column

操作列按钮来自Action Contract，Runtime依据状态、数据和权限解析。页面只处理统一`row-action`，不得硬编码绕开Guard。无动作时显示“暂无可用操作”。

### 5.3 可编辑业务列表

企业列表包含供应商、物料或其他主数据分配字段时，仍必须复用统一列表基座、筛选、固定列和内部滚动契约。主数据字段只能通过受治理选项Provider或当前受治理业务上下文选择，禁止自由输入不存在的主数据；显示名称必须由所选业务编号同步解析。人工选择形成后执行`DATA-PROTECTION-001`，列表筛选、排序、分页、刷新和Provider重载不得改变分配结果。

### 5.4 横向滚动与宽度

页面/Card保持`width/max-width:100%`、`min-width:0`、`overflow-x:hidden`；横向滚动所有权属于表格内部。宽度策略：normal≥1200、wide≥1600、ultra-wide≥1800。验收必须测量`scrollWidth>clientWidth`、`overflowX=auto/scroll`、容器可见且页面根节点无溢出。

## 6. 页面操作指引

页面操作指引与流程导航分离，必须覆盖：

| 编号      | 内容           |
| --------- | -------------- |
| GUIDE-001 | 页面用途       |
| GUIDE-002 | 适用角色       |
| GUIDE-003 | 进入方式       |
| GUIDE-004 | 页面区域       |
| GUIDE-005 | 第一步操作     |
| GUIDE-006 | 关键按钮及条件 |
| GUIDE-007 | 字段填写       |
| GUIDE-008 | 异常处理       |
| GUIDE-009 | 完成判断       |
| GUIDE-010 | 下一步操作     |

只读或无字段页面保留N/A和原因。指引使用业务语言，与页面按钮、字段一致。

## 7. 动作与交互反馈

按钮必须可见、可执行、状态允许、数据完整、权限满足，并在执行后显示业务结果或阻断原因。按钮禁用和事件/API入口执行同一Guard。危险动作需要二次确认、幂等、审计和恢复策略。

页面不得把“存在按钮”当成动作闭环，不得只跳Route，不得在入口点击时自动创建未经授权的下游对象。

## 8. 页面可观测性

页面必须提供只读诊断：pageCode、业务对象、dataMode、factSource、factLoadStatus、resultCount、业务键、危险动作数、业务写入分类和错误契约。共享页面壳的可观测性注册使用实例所有权；旧页面卸载不得清除新页面诊断提供者。

诊断、复制诊断、页面和API复用同一服务端事实。`read_failed`不能显示为0条成功。

## 9. 运行模式

`production/canary_acceptance/demo`必须显式显示并隔离。Production禁止默认读取Demo/Acceptance事实；Canary不得调用生产写接口或污染生产数据。

## 10. 一页一验收

每个可访问页面建立独立Page Acceptance Profile，覆盖页面身份、区域、字段、列表、动作、流程、异常、刷新、GUIDE、权限、模式、可观测性、自动证据和人工证据。结果仅允许`PASS/FAIL/N/A/UNKNOWN`；UNKNOWN和无说明N/A阻断PAGE_READY。

## 11. PROCESS-VISUAL-001 业务流程图展示规范

业务流程中心和流程页面中的业务流程可视化必须满足：

1. 流程节点使用独立业务卡片呈现，禁止退化为横向表格、文本行或被多层容器重复变形；
2. 节点卡片必须具有明确且稳定的盒模型和最小宽度，禁止因父级`flex/grid`收缩或固定小宽度造成阶段名称、状态和入口压缩；
3. 页面根节点、页面壳、内容面板和流程外层容器必须保持`min-width:0`、`max-width:100%`并禁止页面级横向滚动；
4. 长流程的横向滚动所有权只属于流程区域内部，流程轨道必须显式声明`overflow-x:auto/scroll`，不得把滚动传递给页面；
5. 节点至少显示编号、阶段名称、业务状态、页面版本和页面入口；节点顺序与箭头连接必须与流程Registry一致；
6. 响应式变化只能改变流程区域可视宽度，不得改变节点业务顺序、隐藏节点信息或把卡片转换为表格；
7. 自动验收必须检查节点数量、顺序、卡片视觉身份、字段完整性、箭头数量、流程区域滚动所有权和页面级横向溢出；人工验收必须在真实页面确认卡片、箭头、可读性和页面滚动边界。

本规则直接归属于页面与交互开发规范；禁止另建平行的“流程图规范”或“流程可视化规范”。

## 12. ERP-CALCULATION-DISPLAY-001 业务核算解释展示

页面展示建议数量、金额、交期或评分等系统计算结果时，必须同时显示业务名称、计算公式、各输入项含义、事实来源、完整性状态、系统建议与人工确认的区别以及异常阻断原因。技术字段名不得代替ERP业务语言；未知输入显示“未接入/待确认”，不得用空白或零伪装。

人工确认字段必须与建议字段并列可辨，修改建议值时提供原因输入和审计提示。核算说明属于目标页面业务区域，不得为单页新建平行公共组件或独立治理规范。

### 12.1 数量异常聚合展示

同一列表存在多条数量异常时，行内保留中文数量状态（正常、需填写原因、严重异常），详细原因统一汇总到“采购数量核算说明”区域。禁止为每行重复渲染大面积红色告警；严重异常仍必须保持醒目且不得削弱Guard阻断。隐藏或过滤非当前采购内容时，只允许改变页面投影，不得删除草稿证据。

## 13. MULTI-SOURCE-CONTEXT-DISPLAY-001 多来源上下文展示

业务创建页承接多个来源对象时，来源区域必须逐项显示全部来源编号并显示来源数量；禁止只展示第一条、拼接为不可识别文本或用汇总数量替代编号。合并明细的“查看来源”必须能展示全部来源编号，刷新和页面重入后保持一致。

## 14. PAGE-RUNTIME-FREEZE-001 页面运行资产冻结规则

核心业务页面、业务流程中心、SCM/ERP核心页面及已经专项验收的页面，在READY后形成页面运行资产基线。冻结内容包括：

- 页面区域数量、顺序、标题、卡片和表格；
- 按钮位置、操作入口和导航关系；
- 布局、滚动方式、容器关系和横向滚动所有权；
- Page Identity、Page Contract及与流程节点的映射。

后续修改前必须识别冻结版本和基线，输出拟变更项、变更原因、影响页面、兼容策略、视觉/交互回归项和恢复方案。相邻业务增强、样式整理或公共能力修改不得静默改变冻结资产；未完成影响分析、专项验收与回归证据时禁止签发READY。

## 15. FLOW-VISUAL-FREEZE-001 业务流程可视化冻结规则

业务流程中心中已经验收的流程可视化必须冻结流程名称、节点数量、节点顺序、节点关系、箭头方向、流程容器结构和内部滚动方式。例如已经验收的“SCM采购与供应商结算流程”，不得因后续页面或组件开发自动改变。

任何冻结流程的修改必须由专项版本明确授权，并同时完成：

1. 修改前后流程Registry与可视基线对比；
2. 节点、箭头、容器和滚动所有权自动检查；
3. 真实页面视觉回归检查；
4. 受影响入口、页面身份和Golden Path重新验收。

缺少任一适用证据时，`FLOW_VISUAL_FREEZE_CHECK`必须为FAIL。

## 16. COMPONENT-CHANGE-IMPACT-001 公共组件影响检查规则

修改PageShell、FlowRenderer、ListRuntime、TableRuntime、Container组件及其他公共运行组件前，必须扫描全部直接和间接消费者，不得只验证当前目标页面。实施前必须输出`Affected Pages List`，至少包含：

- 公共组件及变更契约；
- 受影响页面的`pageCode/route/module`；
- 影响类型（结构、交互、视觉、滚动、数据或动作）；
- 现有冻结/验收基线；
- 每个页面的自动与人工回归结果。

影响页面无法完整枚举、冻结基线不明、任一消费者未验证或真实页面发生非授权变化时，`COMPONENT_IMPACT_CHECK`必须为FAIL并阻断合并与READY。

## 17. LIST-DISPLAY-001 业务列表字段展示规范

业务列表默认只展示业务用户完成判断和操作所必需的摘要信息。`ObjectId`、`SourceRelations`、完整`GateId`、API地址、Runtime诊断字段、JSON和内部状态码不得作为默认业务列；业务用户只能看到服务端提供的中文状态标签。

来源类字段在列表中显示“已关联Gate”“来源数量：N”等摘要，完整来源关系进入详情页查看。禁止为缩短显示而解析、截断或拼接业务编号生成新的业务身份；列表摘要不改变详情证据和服务端事实。

## 18. TECH-FIELD-SEPARATION-001 技术字段与业务字段隔离规范

业务列表展示决策摘要，详情页面展示完整业务证据，诊断区域用于管理员或开发验收的授权查看。技术事实和诊断能力必须保留，但默认不得占用普通业务页面的主要空间；诊断区域默认折叠，由明确的“查看诊断信息”入口展开。

折叠只改变可见性，不得停止服务端事实加载、删除诊断字段、改变Provider或用页面缓存重算事实。详情页必须继续完整展示适用的Gate、采购申请、询价、核价、供应商推荐等来源链。

## 19. TABLE-ROW-HEIGHT-001 表格行高治理规范

ERP业务列表默认采用紧凑行高。超长文本不得自动撑高整行，必须使用单行截断，并通过Tooltip或详情入口查看；操作列必须保持同一行且固定在右侧，表格内部继续拥有横向滚动。

编辑型表格可以显式声明舒适密度以容纳输入控件，但不得改变业务列表的默认紧凑契约。任何行高优化均不得裁剪输入控件、隐藏业务动作或把横向滚动转移给页面。

## 20. LIST-BUSINESS-CAPABILITY-001 业务列表能力规范

所有ERP业务列表在设计、开发和验收时必须逐项评估以下能力：

1. 导入模板下载；
2. 数据导入；
3. 数据导出；
4. 高级筛选；
5. 排序；
6. 分页；
7. 批量操作；
8. 权限控制；
9. 操作日志。

每项能力必须在Page Contract或Acceptance Profile中标记`Required/Supported/N/A`，并记录业务场景、适用角色、权限、数据范围、Action/Guard、审计和验收入口。`N/A`必须给出明确业务原因；不得因规范列出能力就给只读列表、证据列表或无批量语义页面补造导入、写入或批量动作，也不得以“页面有按钮”代替能力闭环。

高级筛选、排序和分页继续遵守企业列表统一运行契约；权限与日志属于服务端动作事实，页面隐藏、禁用或前端日志不能替代服务端权限校验和审计。

## 21. LIST-IMPORT-001 业务列表导入规范

业务允许导入时，必须同时提供受版本治理的导入模板。模板至少包含业务字段名称、字段说明、数据格式、必填/可选标识、枚举或主数据取值要求、示例和模板版本；禁止以内部`ObjectId`、状态码或未说明JSON作为普通用户必填输入。

导入固定执行`上传 -> 校验 -> 错误反馈 -> 预览 -> 人工确认 -> 受控写入`。校验必须覆盖文件类型、模板版本、字段、格式、必填项、主数据身份、重复业务键、权限、数据范围和适用业务Guard；校验或预览失败时业务写入为0。确认写入必须使用明确Action、幂等键和事务边界，并记录导入人、导入时间、文件摘要、总数、成功数、失败数、业务键、错误明细和写入结果。

禁止未经校验直接写入业务对象，禁止页面解析结果绕过Provider/Domain/Guard，禁止部分失败被描述为整体成功。是否允许部分成功必须由模块专项明确声明，并提供逐项事务、错误和恢复证据；未声明时默认整体阻断。

## 22. LIST-EXPORT-001 业务列表导出规范

业务列表适用导出时，至少支持“导出当前结果”。导出范围必须与当前服务端事实、筛选、排序及用户数据权限一致；选中导出、全量导出或跨页导出属于不同范围，必须向用户明确显示并分别授权。技术字段、隐藏敏感字段和无权查看的数据不得因导出绕过页面隔离。

导出必须记录导出人员、导出时间、页面/业务对象、筛选条件、导出范围、记录数量、业务键摘要、文件格式和结果。导出文件使用业务字段名和服务端业务标签，不得直接输出内部状态码、完整技术关系或诊断字段。导出失败必须显式反馈，禁止用空文件冒充成功。

## 23. BATCH-ACTION-001 业务列表批量操作规范

采购订单、采购申请、销售订单、库存业务及其他具有真实集合语义的列表可以声明批量动作。执行前必须显示已选数量、可执行数量、不可执行数量、影响对象/范围、动作结果和不可执行原因；执行后记录操作者、时间、Action、输入业务键、成功/失败数量、逐项结果和操作日志。

批量动作必须复用Action Contract、权限、服务端Guard、幂等和`Batch Completeness`。`Total=0`、存在不允许状态、数据不完整、权限不足或批次语义要求全部完成而`Pending>0`时，按钮与服务端入口同时阻断并保持原状态。页面多选和循环调用单条按钮不自动构成受治理批量能力；是否允许部分成功必须由模块专项明确，未声明时默认写入前整体阻断。

## 24. COLOR-RULE-001 业务风险颜色规则

交期、库存、审批及其他业务风险颜色必须由明确业务规则或服务端风险标签驱动，开发人员不得按个人偏好在页面局部定义业务颜色。颜色映射必须在业务规则中声明风险等级、中文标签、颜色语义和适用场景，并在同一风险类型的列表、详情、导出说明和验收中保持一致。

颜色只能作为辅助信号，不得成为唯一信息载体；页面必须同时显示中文风险标签，并满足对比度、色觉无障碍和打印/导出可识别要求。未知、未接入或计算失败必须显示“未知/待确认”，不得用正常色掩盖。人工反馈可以形成审计证据，但不得通过页面选色或样式覆盖改变系统风险等级。

## 25. DETAIL-NAVIGATION-001 业务详情页导航规范

所有业务详情页必须在单据业务区域顶部提供“返回列表”“返回上一级”和“刷新”三个明确入口。返回列表进入当前业务对象的稳定列表Route；返回上一级进入当前模块或流程的稳定父页面；刷新重新读取同一业务对象的权威Provider事实，不得创建对象、推进状态或清空人工数据。

详情导航必须使用中文业务标签并保持可见，不得只依赖浏览器后退、面包屑或隐藏图标。直接打开详情Route、来源缺失、历史数据不可追溯时仍须保留三个入口；导航不得通过业务编号解析来源，不得把Route临时参数作为第二数据身份。

## 26. PRINT-FORM-001 PCE-ERP企业打印表单结构规范

ERP业务单据打印必须由独立`BusinessPrintViewModel`承接，固定包含`companyInfo/documentInfo/basicInfo/detailRows/approvalInfo/printMeta`。禁止直接复制或打印页面DOM，禁止把列表、Gate、推荐、报价比较等页面投影当作交易单据明细；打印模型只能读取当前业务对象及其权威明细事实，记录编号字段、明细来源、输入/输出数量和角色权限。

打印表单采用四段式结构：

1. 表单抬头区先独立显示企业名称，换行后以加大、加粗字体显示业务单据名称，二者不得混排；
2. 基本信息区默认采用“字段/值 × 3”的六列紧凑布局，复杂单据可采用“字段/值 × 4”的八列布局。字段按业务执行、计划、辅助信息排序，长文本必须截断、展开或进入独立区域，禁止一个普通字段占满整行；
3. 明细区标题使用“业务名称 + 明细”，列和行只来自当前交易明细集合，不得夹带推荐、比较或未进入当前单据的业务对象；
4. 底部固定提供审批/日期、审核/日期、复核/日期、制表/日期。字段是否显示和可编辑由角色权限决定；空白签字栏不得被系统自动解释或生成为审批结果。

打印、详情、列表和导出必须复用同一业务编号事实及中文业务标签。角色打印投影必须继承页面/导出权限，无权查看的价格、内部审批、成本、历史价格、推荐依据和技术字段不得通过打印泄露。打印预览中的临时签字输入只作用于本次打印；如需持久化，必须另行建立明确Action、权限、Guard和审计，页面不得直接写入业务对象。
