# 采购订单导入模板规范

- 规则编号：`PURCHASE-ORDER-IMPORT-TEMPLATE-002`
- 生效版本：`V1.14.2.8.4.27.2.12`
- 适用范围：采购订单及具有 Header/Detail 聚合结构的业务单据导入模板
- 状态：长期有效

## 1. 目的

业务导入模板必须与受治理业务 Schema 同步，保持单据头与明细的聚合关系。禁止用单个工作表混合 Header 和 Detail 字段，也禁止在下载函数中手工维护少量列。

## 2. 强制工作表结构

采购订单模板固定包含两个业务数据Sheet：

1. `采购订单基本信息`：来自 `PurchaseOrder Header Schema`；
2. `采购订单物料明细`：来自 `PurchaseOrderItem Schema`。

字段说明由Contract作为治理元数据提供，不再形成第三个业务导入Sheet。

其他聚合业务对象按相同原则使用 Header + Detail 两个业务数据工作表；例如销售订单、生产订单不得将头字段和明细字段混入同一数据表。

## 3. 采购订单基本信息

至少包含供应商、采购员、采购日期、计划到货日期、采购订单类型、业务用途、紧急程度、币种、付款条件、交付要求和备注，以及当前 PurchaseOrder Header Schema 声明的其他可导入业务字段。

状态、创建时间、ObjectId、Gate编号和来源关系不得作为普通用户输入字段。`采购订单编号`仅作为Header/Detail导入关联键进入模板，不改变正式编号由Domain生成的规则。

## 4. 采购订单物料明细

至少包含物料编码、物料名称、规格、单位、数量、采购执行单价、金额、计划到货日期和备注。字段唯一来源为 `PurchaseOrderItem Schema`，不得从页面表头或下载函数反向拼列。

## 5. 验收

`PURCHASE-ORDER-IMPORT-TEMPLATE-002`必须验证：

- Sheet Count = 2；
- `采购订单基本信息`和`采购订单物料明细`存在且字段分别匹配 Header/Detail Contract；
- 两个Sheet均包含且仅包含一个`采购订单编号`关联字段；
- 下载文件名为`采购订单导入模板.xlsx`；
- 模板生成与下载业务写入为0。

## 6. 禁止边界

本规范不授权导入写入、采购订单创建、Gate修改、生命周期推进、收货、入库、付款或数据库结构变更。模板下载只生成文件，不形成业务对象。

## 7. IMPORT-TEMPLATE-SCHEMA-BIND-002 Schema绑定门禁

- 生效版本：`V1.14.2.8.4.27.2.13`；
- `采购订单基本信息`字段必须从完整`PurchaseOrder Header Schema`生成；除`objectNo`关联键外过滤`importable=true`；
- `采购订单物料明细`字段必须从完整`PurchaseOrderItem Schema`生成，并在首个业务列加入同一`objectNo`关联键；
- 页面、模板Runtime和下载函数禁止维护第二套字段名称数组；
- Contract必须保留字段名称、系统字段名、是否必填、数据类型和说明元数据；
- 验收必须分别输出Header/Detail的Schema字段、模板字段、Missing和Unexpected，任一差集非空即为FAIL。

## 8. IMPORT-TEMPLATE-STRICT-MATCH-001 模板字段冻结

- 生效版本：`V1.14.2.8.4.27.2.14`；
- 固定生成链为`Schema → PurchaseOrderImportContract → Excel`，Excel Runtime禁止直接导入Schema或手写业务字段；
- `采购订单基本信息`使用纵向结构：`序号 / 字段名称 / 字段值`，字段名称及顺序等于Contract；
- `采购订单物料明细`第一列为`序号`，第二列为`采购订单编号`，其余字段名称及顺序逐项等于PurchaseOrderItem Schema；
- Contract内部字段说明元数据固定为`序号 / Sheet名称 / 显示名称 / 系统字段名 / 是否必填 / 数据类型 / 说明`，不增加第三个导入Sheet；
- 验收必须同时比较Header/Detail字段数量、名称和顺序，任何同义词、缺失、额外字段或顺序变化均为FAIL。

## 9. PURCHASE-ORDER-IMPORT-RELATION-001 Header与Detail关联

- 采购订单导入模板的业务数据Sheet固定为`采购订单基本信息`与`采购订单物料明细`；字段说明作为治理辅助Sheet保留；
- 两个业务数据Sheet第一列均为`序号`，并且都必须包含显示名称完全一致的`采购订单编号`；
- `采购订单编号`是Header与Detail的关联键，系统导入时按该键把多条物料明细归属到对应Header；
- 关联键来自PurchaseOrder/PurchaseOrderItem导入Contract，不得由Excel生成器或页面手写第二套名称；
- Detail缺少关联键、关联键名称不一致、空关联键或找不到Header时必须FAIL；禁止按行号、第一条Header或页面缓存静默关联；
- 正式对象的`objectNo`仍由系统Domain生成；模板中的采购订单编号是导入批次内的关联标识，导入确认时必须经过唯一性与生成策略校验，不得覆盖既有正式对象。

## 10. 变更记录补充

- `V1.14.2.8.4.27.2.15`：新增Header/Detail关联模型和`PURCHASE-ORDER-IMPORT-RELATION-001`。
- `V1.14.2.8.4.27.2.16`：由`IMPORT-RELATION-002`替代旧关联验收表达。两个业务Sheet统一采用横向表格结构：第一行为字段名称，第一列为`序号`，第二列为`采购订单编号`；Detail每条关联键必须命中Header，旧CSV/XLSX生成器删除，不再保留第二套字段或关联逻辑。本条是第8节纵向Header描述的最新替代规则。
