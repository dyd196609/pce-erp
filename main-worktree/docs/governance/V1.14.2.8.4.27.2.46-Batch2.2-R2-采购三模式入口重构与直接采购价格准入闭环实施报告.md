## 已完成治理

1. 采购申请首页形成“新增采购申请 / 既定价格采购 / 直接采购”三个直接入口；通用申请表单移除模式二次选择。
2. STANDARD 保持 MaterialMaster 来源；AGREED_PRICE 建成仅展示 CURRENT SupplierMaterialPrice 的 Batch3 前置入口，不在 R2 创建订单。
3. DIRECT 工作台不再读取既有申请后重新录入，也不再建立物料与价格双数据源；选择供应商后直接加载 CURRENT SupplierMaterialPrice，可选择多条正式价格对象。
4. DIRECT 同一事务由用户一次录入创建一个简化正式 PurchaseRequest、N 个 PurchaseRequestItem、一个统一 PurchaseOrder 和 N 个 PurchaseOrderItem。
5. PurchaseRequestItem 新增 Supplier、SupplierMaterialPrice 和价格快照字段；PurchaseOrder 新增 `source_purchase_request`。订单行与来源申请行一一关联。
6. 数量、计划到货日期、备注与精确价格版本从同一工作台数据贯穿来源申请、订单和正式详情；历史、失效、未生效及跨供应商价格继续由服务端逐行阻断。
7. Gate 为整单预检，创建 API 在同一服务端事实上复核授权与签名；幂等键阻止重复提交生成第二套来源对象。
8. SupplierMaterialPrice Runtime 的 `sourceId` 修正为正式价格记录主键，并补充规格、单位；历史价格仍保留且不进入 CURRENT 可选集。

## 变更范围

- 后端：`procurement` 模型、迁移 `0022`、DIRECT 创建事务、页面事实与序列化输出。
- 前端：采购申请三入口、DIRECT 价格对象工作台、AGREED_PRICE 前置页面、路由与页面身份注册。
- 治理：对象链扫描报告、三模式规范、直接采购规范、R1 FAIL 状态和 R2 验收报告。
