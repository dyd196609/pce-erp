## Automatic vs Runtime Difference

- Database QuerySet：13 条 `PriceApprovalPreparation`，均为 `legacy_verified_fact`；真实报价任务不是 QuerySet 对象。
- Runtime：每次请求从 5 张 `SupplierQuotation` 的 9 个 JSON 明细生成 `SESSION-PAP-*`；`PriceApprovalResult` 与有效价格写入进程字典。
- API：核价 API 返回 13 条持久对象；价格来源 API 另返回 9 条 `sessionAcceptancePreparations`。
- ViewModel：前端执行 `[...sessionAcceptancePreparations, ...result.records]`，形成 22 条混合列表。
- 过滤/状态：9 条会话对象均 completed/pass；持久对象中 12 条 completed（11 pass、1 reject），另 1 条 reviewing。
- 前端/分页：默认每页 20，首部固定为 9 条会话投影；`.45.5` 自动化按前五行选择。
- Cache/Session Memory：归档结果为 `SERVER_MEMORY_ONLY`，当前仍有 5 条；进程重启可丢失。
- 数据库环境：自动化与当前页面均连接实际开发数据库，不是测试数据库；无 Fixture、Mock、独立事务。
- 产生方式：真实页面点击，经 API 调用 Runtime；不是 API 直调、Service 直调、Fixture、Mock 或测试数据库。
- 旧口径：`.45.5` 的 `Browser Human Acceptance: PASS` 来自 Codex 自动浏览器，口径错误，已追加治理更正。
