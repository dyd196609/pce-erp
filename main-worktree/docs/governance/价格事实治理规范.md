# 价格事实治理规范

- 规则编号：`PRICE-FACT-MODEL-001`
- 生效版本：`V1.14.2.8.4.27.2.34`
- 适用范围：供应商报价、报价比较、核价、供应商推荐和采购订单执行价格
- 上位规范：`PCE-ERP智能化开发总纲.md`、`供应商主数据规范.md`、`采购业务生命周期规范.md`
- 状态：基础事实模型已生效；仅授权既有 Runtime 的只读事实投影，不授权价格维护、数据库变更、自动核价、自动推荐或业务写入

## 1. PRICE-SOURCE-TRACE-001 价格必须有来源

每个价格事实必须同时关联物料、供应商、事实时间和来源业务对象。缺少任一身份时不得作为报价比较、核价、推荐或采购订单执行价格。

价格来源链固定为：

```text
SupplierQuotation + SupplierQuoteItem
  -> QuoteComparisonFact
  -> PriceApproval / PriceApprovalPreparation
  -> PurchaseOrderItem.unit_price
```

链中每个节点形成独立、可追溯事实，不得把同一条记录原地改写为下游事实。Gate只传递准入身份和决策证据，不得携带或成为价格来源。页面、前端Store、默认值、MaterialMaster价格及人工复制文本均不是正式价格事实。

## 2. SupplierPriceFactModel 最小契约

`SupplierPriceFactRuntime` 的公开模型固定输出：

| 字段组 | 必需字段 |
|---|---|
| 事实身份 | `priceFactId`、`status`、`statusLabel` |
| 来源 | `sourceType`、`sourceReference`、`sourcePriority` |
| 主数据 | `supplierId`、`supplierCode`、`materialId`、`materialCode` |
| 价格 | `unitPrice`、`currency`、`unit`、`taxRate`、`deliveryPeriod` |
| 时间 | `effectiveDate`、`expiryDate` |
| 治理 | `isTestBasePrice`、`source` |

正式可执行价格必须满足：严格匹配SupplierMaster和MaterialMaster、`unitPrice > 0`、币种明确、有效期命中执行日期、来源对象存在、来源指纹可复核。任何缺失输出`UNKNOWN/FAIL`并阻断，不得用0或最近一条记录兜底。

## 3. 既有能力所有权与 Runtime 实施

Price Fact Runtime不是第二套Runtime。本版本在既有 `backend/masterdata/master_data_statistics_runtime.py` 所有权内增加 `SupplierPriceFactRuntime` 与不可变 `SupplierPriceFactModel`，并复用：

- `SupplierMaterialFactResolver`进行Supplier+Material严格身份解析；
- `SupplierQuotation` 报价明细提供第一优先级价格事实；
- 既有独立 `SupplierMaterialPrice` 持久来源存在时提供第二优先级事实；当前不得把页面样例或报价别名伪装为该来源；
- `PurchaseOrderItem` 仅以只读方式提供第三优先级历史执行价格；
- 现有Schema、Registry、Runtime、来源追踪和权限能力提供展示与访问控制。

同一 `supplierId + materialId + effectiveDate` 只输出一个当前事实，按 `SupplierQuotation > SupplierMaterialPrice > PurchaseOrderHistory` 选择；所有来源候选继续由 `historyModels` 保留，不覆盖、不删除历史。缺少正式有效期的报价必须标记“待补有效期”，不得自动补造。

禁止新建平行Metadata、Registry、Schema、页面价格Store或另一个价格事实数据库；如果最小契约需要数据库字段或新持久对象，必须另立数据库授权版本并提供迁移、兼容、回滚与历史保护方案。

## 4. 价格生命周期

| 事实类型 | 形成条件 | 是否可修改 | 下游用途 |
|---|---|---|---|
| `SUPPLIER_QUOTE` | 供应商报价明细已保存/提交/接收，价格为正 | 按报价生命周期受控 | 比价候选 |
| `QUOTE_COMPARISON` | 多家完整报价证据形成不可变比较事实 | 不可变，只能新增版本 | 核价证据 |
| `APPROVED_PRICE` | 人工核价完成且结论为通过 | 人工Action形成新版本 | 推荐和订单准入 |
| `EXECUTION_PRICE` | 人工创建采购订单时服务端再次解析并固化 | 订单规则约束 | 采购执行与历史分析 |

报价、比较、核价和执行价格是链接事实，不是自动状态推进。报价接收不得自动核价，核价通过不得自动推荐，推荐确认或Gate通过不得自动创建采购订单。

## 5. 历史、最低、最近与趋势

- 历史价格集合只允许纳入身份匹配、正价、币种可比、时间完整且来源可追溯的事实。
- 最低价是指定物料、供应商/候选集合、币种、税口径、有效期和规则版本下的统计结果，不是自动选择结论。
- 最近价按`occurredAt`和稳定业务身份排序；缺少时间时不得声称“最近”。
- 趋势至少需要同一比较口径下两个有序价格点，并输出样本量、区间和规则版本；样本不足时为`INSUFFICIENT_DATA`。
- 历史统计不得覆盖原始报价、核价或订单执行事实。

## 6. 智能匹配、异常与推荐边界

自动价格匹配只能生成候选结果，匹配键固定为严格的`materialId/materialCode + supplierId/supplierCode`，并联合币种、税口径、有效期和来源状态。价格上涨、异常高/低价和供应商偏离必须由受治理阈值、同口径历史窗口和规则版本计算；样本不足不得输出正常。

供应商推荐可以读取价格、交期、质量和历史表现证据，但必须分别标明来源、完整性和权重版本。系统不得自动选择最低价、自动确认推荐或把评分写成采购决定。核价、供应商选择、价格调整、异常豁免和采购订单执行价格均必须由有权限人员通过显式Action确认。

## 7. 测试基础价格

测试数据补充只能在独立授权版本中进行，并必须标记：

```text
factOrigin = DEVELOPMENT_TEST_DATA
isTestBasePrice = true
sourceType = TEST_BASE_PRICE
scenarioId / batchId / generatedAt / validFrom / validTo
```

测试基础价格用于模型和验收，不得标记为供应商真实报价、不得进入Production推荐或采购订单执行价格。生成必须可重建并记录Before/After、业务键和清理方式。本版本不执行任何测试数据补充，Business Write Count 为0。

## 8. 验收门禁

- `PRICE-FACT-SOURCE-001`：来源类型仅允许受治理来源或显式 `TEST_BASE_PRICE`。
- `PRICE-FACT-TRACE-001`：每条事实具有可复核 `sourceReference`，并绑定供应商、物料和时间。
- `PRICE-FACT-UNIQUE-001`：当前模型按供应商、物料、生效日期唯一。
- `PRICE-HISTORY-PROTECT-001`：完整历史候选保留，模型不可变，页面无修改或删除入口。
- `PRICE-NO-AUTO-DECISION-001`：Runtime 与页面均不提供自动核价、推荐、选供应商或下单能力。
- `DUPLICATE-INTELLIGENCE-FRAMEWORK-001`：规划扩展既有Runtime/Schema/Registry，不建立平行框架。
- 数据质量门禁：空价、空供应商、物料无法匹配、有效期缺失和历史样本不足必须计数并显式报告。

## 9. 只读页面与智能扩展点

`#/foundation/erp/supplier-price-facts` 只消费服务端 `SupplierPriceFactRuntime`，并通过既有 Metadata Registry、企业列表、高级筛选和状态组件展示。页面禁止维护价格、补填来源或重新计算事实。

本版本只登记“价格历史分析、价格趋势、异常价格检测、供应商价格比较”四个扩展点。扩展点不代表已作出决策，后续实现仍须单独授权、复用既有智能能力并保持人工确认边界。

## 10. 核价完成与有效价格归档（V1.14.2.8.4.27.2.45.7）

核价完成数不等于有效价格数。核价完成只表示人工核价流程结束；只有能够逐条证明 `SupplierQuotation -> SupplierQuotationItem -> PriceApprovalPreparation -> Human Price Approval -> SupplierMaterialPrice` 的通过结果才可归档。`legacy_verified_fact` 只保留为历史验收事实，`development_test_data` 保留开发测试身份，二者均不得伪装为正式报价来源。

来源程序编码必须保留，业务页面统一消费 `sourceTypeLabel`。未知来源显示“未登记来源”，不得把中文标签回写为事实类型。

企业采购默认税率的唯一配置为 `django.conf.settings.PCE_ENTERPRISE_PROCUREMENT_DEFAULT_TAX_RATE`。归档优先继承报价的合法标准税率，否则使用企业默认税率；允许值为 0、3、6、9、13。有效价格页面只允许授权人员维护税率、生效日期、失效日期并记录修改人、时间、旧税率、新税率和原因。该维护不得改写 `SupplierPriceFact`。

## 11. PriceApprovalResult 权威归档（V1.14.2.8.4.27.2.45.8）

`SupplierQuotation` 不是有效价格的唯一合法前置来源。正式归档链为 `Original Price Fact -> PriceApprovalPreparation -> 人工核价与供应商选择 -> PriceApprovalResult -> SupplierMaterialPrice`。原始事实可以是已登记的正式报价、历史验收事实或开发测试事实，但历史/测试事实均不得直接价格化；只有本次显式确认形成的持久 `PriceApprovalResult` 才是新价格的批准依据，且 `originalSourceType/originalSourceReference` 不得篡改。

`SupplierMaterialPrice` 必须持久化。生效日期依次取报价确认时间、供应商最终人工确认时间、核价通过时间的日期部分；不得取报价创建日、系统当天默认值或前端时间。当前确认动作存在时取服务端 `confirmedAt`。失效日期默认空，由授权人员维护。

## 12. 归档阻断与运行闭环（V1.14.2.8.4.27.2.45.9）

归档前必须分别校验核价完成、核价通过、人工供应商选择、供应商主数据、物料主数据、核准价格和币种。供应商或物料无法映射时分别返回 `SUPPLIER_MAPPING_FAILED` 或 `MATERIAL_MAPPING_FAILED`，不得显示为待确认报价，也不得通过字符串猜测主数据。正式价格四层同对象规则为 `Database = SupplierMaterialPriceRuntime = API = Browser`。
