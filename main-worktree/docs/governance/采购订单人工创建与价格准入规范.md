# 采购订单人工创建与价格准入规范

## 1. 适用范围

本规范适用于 STANDARD（标准采购）的 PurchaseOrder Direct Creation（采购订单直接创建）。AGREED_PRICE（既定价格采购）和 DIRECT（直接采购）不属于本规范当前开放范围。

## 2. 人工创建顺序

采购模式选择 → SupplierMaster（供应商主数据）选择 → MaterialMaster（物料主数据）选择 → 数量输入 → SupplierMaterialPrice（供应商物料价格）批次选择 → 订单信息确认 → 人工确认 → PurchaseOrderGate（采购订单准入门禁） → 显式创建。

任一环节不得由页面打开、刷新、默认第一项、最低价、最新价、上一页缓存或前端推算代替人工选择。

## 3. 主数据与供应关系

1. 供应商必须来自已启用的 SupplierMaster。
2. 物料必须来自已启用、允许采购且规格和单位完整的 MaterialMaster。
3. 供应商与物料必须存在服务端 MaterialSupplierRelation。
4. 页面显示值、Gate 检查值、正式订单快照和验收报告必须复用同一服务端事实。

## 4. 价格准入

1. 页面必须展示选定供应商与物料范围内的全部正式价格版本。
2. 当前价格、历史价格、未来价格和停用价格必须明确区分。
3. 普通新标准采购订单只允许人工选择订单日期下的当前适用价格。
4. 历史价格必须保留并可追溯，但不得用于普通新订单。
5. 无正式价格时必须阻断，不允许手填自由价格，不允许自动回退历史价格。
6. 价格匹配必须同时校验 SupplierMaterialPrice 主键和业务编号；禁止模糊匹配。
7. 订单必须保存 SupplierMaterialPrice、PriceApprovalResult 外键以及单价、税率、币种、物料和供应商快照。
8. 后续价格版本变化不得反向覆盖已创建订单的执行快照。

## 5. Gate 与创建

Gate Preview（门禁预检）是只读操作，至少检查供应商主数据、物料主数据、供应关系、正数量、价格准入和人工创建上下文。通过后签发与完整上下文绑定的短期 Admission Token（准入令牌）。

正式创建必须同时满足：人工确认、有效令牌、上下文未变化、显式 POST 动作。任何字段变化都应使既有准入结果失效并要求重新检查。

## 6. 幂等与零隐式创建

每次空白工作台会话生成唯一 Idempotency Key（幂等键）。同一键重复提交只能返回既有 PurchaseOrder，不得新增第二张订单。GET、页面加载、页面刷新、基础资料刷新、价格查询、预览和 Gate 检查的 PurchaseOrder 写入数必须为 0。

## 7. 批次边界

- Batch2.2 只开放 STANDARD。
- AGREED_PRICE 在 Batch3 建设前保持禁用。
- DIRECT 在 Batch4 建设前保持禁用。
- 不得借直接创建入口修改 SupplierMaterialPrice 正式价格或覆盖历史价格。
