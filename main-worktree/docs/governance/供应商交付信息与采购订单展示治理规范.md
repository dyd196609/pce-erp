# 供应商交付信息与采购订单展示治理规范

- 规则编号：`SUPPLIER-DELIVERY-ADDRESS-001`、`PURCHASE-ORDER-SUPPLIER-VIEW-001`、`PURCHASE-ORDER-PRINT-SUPPLIER-001`
- 生效版本：`V1.14.2.8.4.27.2.28`
- 适用范围：SupplierMaster、采购订单列表、采购订单详情与采购订单打印预览
- 状态：长期有效、持续更新

## 1. SupplierMaster 交付地址

SupplierMaster 必须独立持久化注册地址与物流送货地址：

- `address`：供应商注册地址；
- `deliveryAddress`（服务端字段 `delivery_address`）：物流送货地址。

两个字段不得互相覆盖或由页面临时复制。现有测试供应商的物流送货地址允许使用“省 + 市 + 公司”结构的模拟数据；禁止修改供应商编码。

## 2. 采购订单供应商展示来源链

采购订单只读展示的供应商信息固定来源链为：

```text
SupplierMaster
-> PurchaseOrder.supplier
-> ScmStandardPageFacts supplier projection
-> PurchaseOrderListDataProvider
-> PurchaseOrderRuntimeModel
-> PurchaseOrder Supplier Schema
-> Detail / Print DOM
```

订单详情和打印预览必须展示供应商名称、联系人、联系电话、供应商地址和送货地址。页面不得手工填写、拼接、回退到 Gate、报价、上一页缓存或订单备注。

服务端订单只读投影使用 `supplierDeliveryAddress` 表达 SupplierMaster 的物流送货地址，与采购订单自身既有的订单级 `deliveryAddress` 语义隔离。

## 3. 列表宽度边界

采购订单列表只允许增加或保留 `supplierName`（供应商名称）。联系人、联系电话、供应商地址和送货地址不得进入列表列定义，避免列表过宽。

## 4. 验收门禁

- `SUPPLIER-DELIVERY-ADDRESS-001`：全部 SupplierMaster 的 `delivery_address` 非空、非占位，并符合“省 + 市 + 公司”测试数据结构。
- `PURCHASE-ORDER-SUPPLIER-VIEW-001`：详情页五个供应商字段均来自同一 SupplierMaster 服务端投影，且为只读。
- `PURCHASE-ORDER-PRINT-SUPPLIER-001`：打印 ViewModel 和打印 DOM包含同一组五个供应商字段，不复制详情页面 DOM，不从页面重算。
- 采购订单列表列集合包含 `supplierName`，且不包含联系人、电话、注册地址和送货地址字段。
- 本规则只允许供应商基础资料补充写入；采购订单、价格、交期、MaterialMaster 和 Gate 的业务写入必须为零。

任一适用门禁为 `FAIL` 或 `UNKNOWN` 时，不得输出 `SUPPLIER_DELIVERY_INFO_RUNTIME_READY`。
