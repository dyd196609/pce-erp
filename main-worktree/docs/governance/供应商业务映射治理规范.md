# 供应商业务映射治理规范

> V1.14.2.8.4.27.2.45.11 补充：历史业务供应商编码只能通过唯一业务证据形成显式 `SupplierBusinessReferenceMapping`，正式动作统一解析至 SupplierMaster；禁止去连接符、补零、去零、前缀替换和顺序猜测。完整规则见《采购业务主数据引用治理规范》的 `MASTER-DATA-REFERENCE-CLOSURE-001`。

- 规则编号：`SUPPLIER-BUSINESS-MAPPING-001`
- 生效版本：`V1.14.2.8.4.27.2.26`
- 状态：长期有效、持续更新

## 1. 唯一来源

`procurement.Supplier`（SupplierMaster，数据库表 `supplier`）是供应商编码、名称、联系人、联系电话、地址、分类、状态和等级的唯一来源。业务模块只能保存SupplierMaster身份及业务时点快照，禁止页面临时供应商、Gate临时供应商和静态验收供应商进入正式页面或交易链。

## 2. 业务反向映射

允许从采购申请、询价、报价、比较、核价、推荐、Gate和采购订单的既有事实中提取供应商身份，形成只读 `SupplierBusinessMapping`。映射顺序为完整Supplier ID、完整Supplier Code、唯一Supplier Name；多个身份必须指向同一SupplierMaster，否则进入人工确认清单。

禁止改变大小写、删除连字符、替换前缀、补零或按名称猜测编码。业务事实只能证明“某SupplierMaster被使用”，不能反向生成价格、交期、评分或未经证实的联系资料。

## 3. 页面来源

`#/master-data/suppliers` 必须通过 `SupplierMasterRuntimeAdapter` 读取 `procurement.Supplier`。`enterprise_master_data.py`、业务模块Store、Gate Context和页面state不得作为SupplierMaster页面数据源。

## 4. 验收门禁

- `SUPPLIER-MASTER-SOURCE-001`：维护页、Runtime、业务引用均指向SupplierMaster。
- `SUPPLIER-BUSINESS-MAPPING-001`：所有业务供应商引用唯一映射或进入人工确认清单。
- `SUPPLIER-FIELD-COMPLETE-001`：编码、名称、联系人、电话、地址、分类、状态、等级均有真实SupplierMaster值；“未维护”只用于诊断，不能计为完整。
- `SUPPLIER-DUPLICATE-001`：编码不得重复；同名记录必须有独立身份依据，否则阻断名称映射并进入人工确认。

任一适用门禁存在FAIL或UNKNOWN时不得输出READY。
